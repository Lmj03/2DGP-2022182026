# LEC10 키보드 입력 캐릭터 이동 PRD

## 1. 문서 정보

- 제품명: 전 방향 키 입력 캐릭터 이동
- 대상 경로: `Labs/LEC10_HandlingInputs`
- 실행 파일: `all_direction_key_input.py`
- 입력 이미지: `animation_sheet.png`
- 배경 이미지: `TUK_GROUND.png`
- 기술 스택: Python, `pico2d`
- 문서 상태: 개발 기준 문서

## 2. 제품 개요

`animation_sheet.png`의 소년 캐릭터를 `pico2d` 창에 표시하고, 사용자가 상하좌우 방향키를 눌러 화면 안에서 이동시킬 수 있는 학습용 2D 게임 프로그램이다. 이동 방향에 따라 적절한 애니메이션을 재생하며, 캐릭터가 이동하지 않을 때에는 IDLE 애니메이션을 재생한다.

좌우 이동은 캐릭터가 실제 이동 방향을 바라보도록 한다. 상하 이동은 현재 바라보는 좌우 방향을 유지한다. 입력이 없을 때에도 마지막으로 바라본 방향을 유지한다.

## 3. 목표와 범위

### 3.1 목표

1. `pico2d`로 게임 창을 열고 `TUK_GROUND.png`를 배경으로 출력한다.
2. `animation_sheet.png`에서 소년 캐릭터의 이동 및 IDLE 프레임을 출력한다.
3. 상하좌우 방향키로 캐릭터를 네 방향으로 이동시킨다.
4. 좌우 이동 시 캐릭터가 이동 방향을 바라보도록 전환한다.
5. 상하 이동 시 기존 좌우 방향을 유지한다.
6. 아무 키도 누르지 않을 때 IDLE 애니메이션을 재생한다.
7. 캐릭터가 화면 경계를 벗어나지 않도록 위치를 제한한다.
8. 최소 20개의 작은 논리 단위 커밋으로 개발 과정을 남기며, 모든 커밋 메시지는 한글로 작성한다.

### 3.2 범위에 포함하지 않는 기능

- 마우스 이동 및 마우스 클릭 처리
- 점프, 공격, 충돌, 체력, 점수 시스템
- 적 캐릭터나 아이템
- 사운드 및 배경 음악
- 별도 HUD 또는 메뉴 화면
- 네트워크 기능과 저장 기능
- 여러 캐릭터 선택 기능

## 4. 사용자 시나리오

1. 사용자가 `Labs/LEC10_HandlingInputs`에서 `python all_direction_key_input.py`를 실행한다.
2. 프로그램은 `TUK_GROUND.png`를 배경으로 창을 열고 소년 캐릭터를 화면에 표시한다.
3. 사용자가 위, 아래, 왼쪽, 오른쪽 방향키를 누르면 캐릭터가 해당 방향으로 이동한다.
4. 사용자가 왼쪽 또는 오른쪽 방향키를 누르면 캐릭터의 좌우 바라보는 방향이 바뀐다.
5. 사용자가 위 또는 아래 방향키를 누르면 캐릭터는 현재 좌우 방향을 유지한 채 이동한다.
6. 사용자가 모든 방향키를 놓으면 캐릭터가 현재 바라보는 방향을 유지하면서 IDLE 애니메이션을 재생한다.
7. 캐릭터가 화면 가장자리에 도달하면 화면 밖으로 이동하지 않고 경계 안에 멈춘다.
8. 사용자가 창을 닫으면 프로그램이 정상적으로 종료된다.

## 5. 기능 요구사항

### FR-01. 창 초기화

- `pico2d.open_canvas()`로 실행 창을 연다.
- 창 크기는 배경 이미지와 캐릭터가 충분히 표시되는 고정 크기로 설정한다.
- 배경 이미지는 매 프레임 캐릭터보다 먼저 그린다.
- 프로그램 종료 시 `close_canvas()`를 호출한다.

### FR-02. 이미지 로드

- `animation_sheet.png`를 캐릭터 스프라이트 시트로 사용한다.
- `TUK_GROUND.png`를 배경 이미지로 사용한다.
- 실행 위치가 달라져도 스크립트 기준 경로에서 이미지 리소스를 찾을 수 있도록 구성한다.
- 이미지 파일을 불러오지 못하면 파일 경로가 포함된 오류를 출력하고 무한 루프에 진입하지 않는다.
- 스프라이트 시트 전체를 그대로 출력하지 않고 필요한 프레임 영역만 잘라서 출력한다.

### FR-03. 키보드 입력 처리

- `SDL_KEYDOWN` 이벤트에서 상하좌우 방향키 입력 상태를 기록한다.
- `SDL_KEYUP` 이벤트에서 해당 방향키의 입력 상태를 해제한다.
- 여러 방향키가 동시에 눌리는 경우에도 프로그램이 오류 없이 동작한다.
- 방향키 외 입력은 이동에 영향을 주지 않는다.
- `SDL_QUIT` 이벤트가 발생하면 메인 루프를 종료한다.
- 선택 사항으로 `ESC` 키를 눌렀을 때 프로그램을 종료할 수 있다.

### FR-04. 캐릭터 이동

- 위 방향키를 누르면 캐릭터의 y 좌표를 증가시킨다.
- 아래 방향키를 누르면 캐릭터의 y 좌표를 감소시킨다.
- 오른쪽 방향키를 누르면 캐릭터의 x 좌표를 증가시킨다.
- 왼쪽 방향키를 누르면 캐릭터의 x 좌표를 감소시킨다.
- 대각선 입력이 들어오면 두 축의 이동을 모두 반영한다.
- 이동 속도는 프레임 속도에 지나치게 의존하지 않도록 일정한 기준으로 관리한다.
- 캐릭터의 기준점은 프레임이 바뀌어도 일관되게 유지한다.

### FR-05. 방향 전환

- 왼쪽 이동 시 캐릭터가 왼쪽을 바라보는 방향 상태로 변경된다.
- 오른쪽 이동 시 캐릭터가 오른쪽을 바라보는 방향 상태로 변경된다.
- 위 또는 아래 이동만 발생한 경우에는 기존 좌우 방향 상태를 변경하지 않는다.
- 입력이 없거나 IDLE 상태일 때에도 마지막 좌우 방향 상태를 유지한다.
- 스프라이트 시트의 방향 프레임 또는 좌우 반전 기능 중 기존 리소스에 맞는 방식을 사용한다.

### FR-06. 애니메이션

- 이동 중에는 이동 방향에 맞는 이동 애니메이션을 재생한다.
- 아무 방향키도 입력되지 않으면 IDLE 애니메이션을 재생한다.
- IDLE 상태에서 프레임을 반복하되 캐릭터의 위치는 변경하지 않는다.
- 위아래 이동 중에는 좌우 방향 상태에 맞는 캐릭터 이미지를 유지한다.
- 프레임 번호는 각 애니메이션의 프레임 범위를 벗어나지 않는다.
- 프레임 전환 속도는 코드의 상수로 관리하고 이동 속도와 분리한다.

### FR-07. 화면 경계 처리

- 캐릭터의 전체 크기를 고려해 화면 왼쪽 경계 밖으로 나가지 않도록 한다.
- 캐릭터의 전체 크기를 고려해 화면 오른쪽 경계 밖으로 나가지 않도록 한다.
- 캐릭터의 전체 크기를 고려해 화면 위쪽 경계 밖으로 나가지 않도록 한다.
- 캐릭터의 전체 크기를 고려해 화면 아래쪽 경계 밖으로 나가지 않도록 한다.
- 경계에 도달한 뒤 해당 방향 입력을 계속해도 캐릭터가 화면 밖으로 이동하지 않는다.

### FR-08. 종료 처리

- 창 닫기 이벤트가 발생하면 입력 및 그리기 반복을 중단한다.
- 종료 시 이미지 리소스와 캔버스를 정상적으로 정리한다.
- 종료 후 프레임 재생 루프가 남아 있지 않아야 한다.

## 6. 상태 및 재생 규칙

캐릭터는 다음 상태 정보를 가진다.

- 현재 위치: `x`, `y`
- 현재 애니메이션 프레임: `frame`
- 현재 좌우 바라보는 방향: `facing_direction`
- 현재 입력 상태: 상, 하, 좌, 우 키의 눌림 여부
- 현재 동작 상태: `IDLE` 또는 `MOVE`

프레임별 처리 순서는 다음과 같다.

```text
이벤트 수집
  -> 방향키 입력 상태 갱신
  -> 이동 방향 계산
  -> 좌우 방향 상태 갱신
  -> 화면 경계 안으로 위치 제한
  -> IDLE 또는 이동 애니메이션 프레임 선택
  -> 배경 출력
  -> 캐릭터 출력
  -> 화면 갱신
  -> 다음 프레임까지 대기
```

방향 규칙은 다음과 같다.

```text
왼쪽 입력  -> x 감소, 왼쪽 바라보기
오른쪽 입력 -> x 증가, 오른쪽 바라보기
위 입력    -> y 증가, 좌우 방향 유지
아래 입력  -> y 감소, 좌우 방향 유지
입력 없음  -> 위치 유지, 좌우 방향 유지, IDLE 재생
```

여러 키가 동시에 입력될 때의 이동량은 각 축별 입력을 합산한다. 동일 축의 반대 방향 키가 동시에 눌리면 해당 축의 이동량은 0으로 처리한다.

## 7. 화면 및 출력 요구사항

- 배경과 캐릭터가 명확히 구분되어야 한다.
- 배경은 매 프레임 화면 전체에 출력한다.
- 캐릭터는 화면 안에서 식별 가능한 크기로 출력한다.
- 캐릭터가 이동할 때 잔상이 남지 않아야 한다.
- 캐릭터가 화면 경계에 닿아도 일부가 잘리지 않아야 한다.
- 좌우 이동 시 캐릭터의 시각적 방향이 이동 방향과 일치해야 한다.
- 상하 이동 시 좌우 바라보는 방향이 갑자기 바뀌지 않아야 한다.
- IDLE 상태에서도 마지막 좌우 방향이 유지되어야 한다.

## 8. 구현 구조

파일은 하나만 추가한다.

```text
Labs/LEC10_HandlingInputs/
├─ all_direction_key_input.py
├─ animation_sheet.png
├─ TUK_GROUND.png
├─ pre-prd.md
└─ prd.md
```

권장 코드 구성은 다음과 같다.

1. `pico2d` 및 필요한 표준 라이브러리 import
2. 화면 크기, 이동 속도, 프레임 속도 상수 정의
3. 스프라이트 프레임 좌표와 애니메이션 데이터 정의
4. 이미지 경로 구성 및 리소스 로드
5. 키보드 이벤트를 처리하는 함수 작성
6. 입력 상태에 따른 이동 및 방향 상태 계산
7. 화면 경계 안으로 좌표 제한
8. IDLE 및 이동 프레임을 선택하는 함수 작성
9. 배경과 캐릭터를 그리는 메인 루프 작성
10. 창 종료 및 리소스 정리

입력 처리, 이동 계산, 애니메이션 선택, 그리기 로직은 가능한 한 분리한다. 프레임 좌표는 재생 제어 코드와 분리해 한 곳에서 수정할 수 있도록 한다.

## 9. 오류 및 경계 조건

- 이미지 파일이 없을 때: 파일 경로를 포함한 오류를 출력하고 안전하게 종료한다.
- 스프라이트 프레임 좌표가 이미지 영역을 벗어날 때: 해당 좌표를 수정하고 잘못된 프레임을 조용히 사용하지 않는다.
- 애니메이션 프레임 목록이 비어 있을 때: 오류를 알리고 재생하지 않는다.
- 창이 닫힐 때: 다음 입력 처리나 그리기를 수행하지 않고 종료 절차로 이동한다.
- 키를 누른 채 창을 닫을 때: 종료를 우선 처리한다.
- 반대 방향 키가 동시에 눌릴 때: 해당 축의 이동량을 0으로 처리한다.
- 화면 경계에 도달했을 때: 캐릭터 이미지의 반 크기를 고려해 좌표를 제한한다.
- 프레임 속도와 이동 속도가 달라져도 캐릭터 위치가 비정상적으로 튀지 않아야 한다.
